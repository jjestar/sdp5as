Подготовка к защите

Тема: вывод списка покупок разными способами.

Объяснение примерно на минуту

Моя программа показывает один список покупок в разных форматах. Я использую паттерн Strategy, чтобы вынести каждый алгоритм форматирования в отдельный класс.

Интерфейс ListFormatStrategy содержит метод format. Его реализуют BulletListStrategy, NumberedListStrategy и CommaSeparatedListStrategy. Они выводят товары с маркерами, с номерами и через запятую.

Контекст ShoppingListFormatter хранит ссылку на интерфейс стратегии. Его метод format передаёт работу выбранной стратегии. Метод setStrategy позволяет заменить алгоритм во время выполнения программы.

Клиент Main создаёт один контекст, выбирает стратегии и печатает результат. В контексте нет if или switch для выбора алгоритма, потому что используется полиморфизм.

Для расширения я добавил CheckboxListStrategy и отдельный клиент ExtensionDemo. Основные классы менять не понадобилось. Это показывает Open Closed Principle.

Вопросы и короткие ответы

1. Что такое Strategy?
Это поведенческий паттерн. Он объединяет взаимозаменяемые алгоритмы общим интерфейсом и позволяет выбирать нужный алгоритм во время работы программы.

2. Какая здесь семья алгоритмов?
Алгоритмы преобразования списка товаров в текст. Вход и тип результата одинаковые, а правила форматирования разные.

3. Где четыре основные роли?
Strategy — ListFormatStrategy.
Concrete Strategies — BulletListStrategy, NumberedListStrategy, CommaSeparatedListStrategy.
Context — ShoppingListFormatter.
Client — Main.

4. Что такое делегирование?
Объект передаёт выполнение другой сущности. Здесь контекст вызывает strategy.format(items), а конкретная стратегия формирует строку.

5. Где происходит переключение во время работы?
В Main через formatter.setStrategy(...). Объект formatter уже создан и остаётся тем же. Вызов его метода format после замены стратегии даёт другой результат.

6. Почему не нужен if или switch?
Поле strategy содержит объект конкретной реализации. Java вызывает его реализацию format через общий интерфейс. Это полиморфизм.

7. Почему здесь композиция?
Контекст содержит ссылку на объект стратегии. Он использует этот объект для выполнения работы. Контекст не наследует конкретный алгоритм.

8. Как добавить новый формат?
Создать класс, реализующий ListFormatStrategy, написать его метод format и передать экземпляр контексту. Пример — CheckboxListStrategy. ExtensionDemo показывает использование новой стратегии без изменения старых классов.

9. Чем Strategy отличается от обычного набора методов?
Алгоритмы оформлены как отдельные взаимозаменяемые объекты с общим интерфейсом. Контекст не выбирает именованный метод каждого формата, а выполняет один и тот же вызов strategy.format(items).

10. Что значит implements?
Класс реализует интерфейс и предоставляет реализацию объявленного в нём метода.

11. Что значит @Override?
Это аннотация, которая позволяет компилятору проверить, что метод реализует или переопределяет существующий метод. Это не комментарий.

12. Что делает StringJoiner?
Собирает несколько строк с указанным разделителем. В стратегиях разделитель "\n" переносит каждый следующий товар на новую строку. add добавляет строку, toString возвращает готовый текст.

13. Зачем в NumberedListStrategy написано i + 1?
Индекс первого элемента равен нулю, а нумерация списка должна начинаться с единицы.

14. Что делают List, Arrays.asList и String.join?
List<String> — список строк. Arrays.asList создаёт список из перечисленных товаров. String.join(", ", items) объединяет товары в строку через запятую и пробел.

15. Какие принципы Clean Code применены?
Полиморфизм — вместо условий выбора вызывается strategy.format.
Понятные имена — название каждого класса объясняет его формат.
Single Responsibility — стратегия отвечает за один формат, клиент за запуск и вывод.
Независимость контекста — он использует только интерфейс.
Open Closed Principle — новый формат добавляется новым классом.
Инкапсуляция — поле strategy закрыто через private.

16. Почему нет меню с вводом пользователя?
Требуется переключение во время выполнения, а не обязательное меню. Main демонстрирует смену стратегии у уже существующего контекста в одном запуске.

17. Меняются ли исходные данные?
Нет. Стратегии читают товары, сохраняя их порядок, и возвращают новую строку. Для пустого списка возвращается пустая строка. Пример предполагает, что стратегия, список и товары не равны null.

18. Когда этот паттерн полезен и какой у него минус?
Он полезен, когда одну задачу можно решить несколькими взаимозаменяемыми алгоритмами и их нужно выбирать или расширять. Минус — появляются дополнительные классы; для одного неизменного алгоритма такая структура может быть лишней.

Что уметь написать на бумаге

1. Интерфейс ListFormatStrategy с методом String format(List<String> items).
2. Одну конкретную стратегию, например CommaSeparatedListStrategy.
3. Контекст с private ListFormatStrategy strategy, конструктором, setStrategy и делегированием.
4. Создание контекста и один вызов setStrategy в клиенте.
5. Пять принципов Clean Code с примерами из этого проекта.

Как запомнить связи

Main создаёт стратегию и передаёт её в ShoppingListFormatter.
ShoppingListFormatter хранит ListFormatStrategy и вызывает его метод format.
Конкретные стратегии реализуют ListFormatStrategy.

Проверь себя без подсказок: объясни, почему при замене стратегии контекст остаётся прежним, а результат меняется.
