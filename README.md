# Shopping List Formatting

Assignment 5 — Strategy pattern, Java.

Тема: вывод списка покупок разными способами. Один список можно представить с маркерами, с нумерацией или через запятую. Способ форматирования меняется во время работы программы через паттерн Strategy.

## Запуск

Нужен JDK 8 или новее. Открой терминал в папке `shopping-list-strategy`, где находится этот README.

```text
javac -d out src/*.java
java -cp out Main
```

Результат:

```text
Bullet list:
- Milk
- Bread
- Apples

Numbered list:
1. Milk
2. Bread
3. Apples

Comma-separated list:
Milk, Bread, Apples
```

Для примера расширения:

```text
javac -cp out -d out extension/*.java
java -cp out ExtensionDemo
```

Результат:

```text
Comma-separated list:
Milk, Bread, Apples

Checkbox list:
[ ] Milk
[ ] Bread
[ ] Apples
```

В IntelliJ IDEA можно создать обычный Java-проект, выбрать JDK, скопировать файлы из `src` в исходники проекта и запустить `Main.main()`. Для примера расширения добавь туда два Java-файла из `extension` и запусти `ExtensionDemo.main()`.

## Компоненты Strategy

| Роль | Класс | Задача |
| --- | --- | --- |
| Strategy | `ListFormatStrategy` | Объявляет общий метод `format(List<String> items)` |
| Concrete Strategy | `BulletListStrategy` | Добавляет маркер перед каждым товаром |
| Concrete Strategy | `NumberedListStrategy` | Добавляет порядковый номер перед каждым товаром |
| Concrete Strategy | `CommaSeparatedListStrategy` | Соединяет товары через запятую |
| Context | `ShoppingListFormatter` | Хранит стратегию, делегирует ей форматирование и позволяет её заменить |
| Client | `Main` | Создаёт стратегии, назначает их контексту и печатает результат |
| Новая Concrete Strategy | `CheckboxListStrategy` | Добавляет поле для отметки перед каждым товаром |
| Клиент расширения | `ExtensionDemo` | Подключает новую стратегию без изменения файлов из `src` |

`Main` создаёт один объект `formatter`. Затем два вызова `setStrategy(...)` меняют его поведение на том же списке товаров. Это переключение во время выполнения: новый контекст не создаётся, перезапуск программы не нужен.

Стратегии получают список строк и возвращают строку. Они сохраняют порядок товаров и не изменяют исходный список. Для пустого списка результатом будет пустая строка. Стратегия, список и его элементы должны быть не `null`.

## Принципы Clean Code

1. **Полиморфизм вместо выбора через условия.** Контекст всегда вызывает `strategy.format(items)`. Нужная реализация определяется объектом стратегии. В проекте нет `if`, `switch` и проверок типа для выбора алгоритма.
2. **Понятные имена.** `NumberedListStrategy` явно обозначает нумерацию, `setStrategy` — замену стратегии, `format` — форматирование списка. Названия описывают назначение без комментариев в коде.
3. **Single Responsibility.** Каждая стратегия отвечает за один способ форматирования. Контекст отвечает за работу с выбранной стратегией. Создание объектов и вывод в консоль находятся в клиенте. Изменение формата не требует правки кода вывода.
4. **Независимость контекста от алгоритмов.** Поле `strategy` имеет тип интерфейса `ListFormatStrategy`. Контекст не знает конкретных классов, разделителей и правил нумерации. Его метод `format` только делегирует вызов.
5. **Open Closed Principle.** Новый формат добавляется новой реализацией интерфейса. Папка `extension` содержит только два новых файла: стратегию и клиент. Для их запуска не нужно менять `ListFormatStrategy`, `ShoppingListFormatter`, `Main` или существующие стратегии.
6. **Инкапсуляция.** Поле `strategy` закрыто с помощью `private`. Клиент меняет его через явно названный метод `setStrategy`, а детали форматирования остаются внутри каждой стратегии.

## Как показать расширение

Сначала запусти основной пример только из `src`. Затем скомпилируй файлы из `extension` и запусти `ExtensionDemo`. Он использует уже скомпилированные основные классы и переключает тот же контекст с формата через запятую на формат с полями для отметки. Исходники основного примера остаются прежними.
